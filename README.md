# Poizon: сайт + Telegram-бот

Заказ одежды и обуви с Poizon: покупатель работает только с Telegram-ботом,
сайт — закрытая админка (без входа доступна лишь страница логина, поисковики её не индексируют).
Администратор ведёт заказы в боте или на сайте. Сайт — FastAPI + Vue 3, бот — aiogram 3,
общая база (PostgreSQL / SQLite) и общая логика цены и статусов в `backend/app/core`.

## Что умеет

**Бот (клиент):** меню «Рассчитать цену / Оформить заказ / Мои заказы / Помощь»;
калькулятор; оформление заказа через FSM с «Отменой» на каждом шаге
(ссылка → скриншот → размер → категория → цена → ФИО → телефон → ПВЗ → подтверждение);
ручная оплата: реквизиты → «Я оплатил» → чек; отмена до оплаты; уведомления о каждом статусе,
при «Отправлен в РФ» — с трек-номером.

**Бот (администратор, `ADMIN_IDS`):** карточка нового заказа со скриншотом и кнопками статусов;
чек от клиента с кнопками «Подтвердить оплату» / «Отклонить чек»; при «Отправлен в РФ» бот
спрашивает трек-номер; `/orders` с фильтром по статусу, `/order N`, `/track`, `/settings`,
`/rate`, `/markup`, `/delivery`, `/requisites`.

**Сайт (только админка):** сводка, заказы с фильтрами и поиском, карточка заказа (скриншот, чек,
история статусов, смена статуса, трек-номер), настройки курса, наценки, доставки и реквизитов.
Любое действие на сайте сразу отправляет клиенту сообщение в Telegram.

**Курс юаня — автоматически с ЦБ РФ.** API раз в час (и при старте) берёт курс CNY с cbr.ru
(запасной источник — cbr-xml-daily.ru). Курс для расчёта = курс ЦБ × (1 + надбавка %).
Надбавку задают на сайте («Настройки») или командой `/rate auto 3`. Если ЦБ не ответил — действует
прежний курс, ошибка видна в настройках. Ручной курс: переключатель «Вручную» или `/rate 12.5`.
Цена в уже оформленных заказах не меняется.

## Статусы (по схеме из ТЗ)

```
Новый → Ожидает оплаты → Оплачен → Выкуплен → На складе в Китае → Отправлен в РФ → В пункте выдачи → Получен
  └──────────┴→ Отменён (до оплаты)     └→ Возврат денег (товара нет или цена выросла)
```
Администратор переводит заказ только в следующий статус или в ветку отмены.
«Новый → Ожидает оплаты» — администратор проверил наличие и цену; в этот момент бот
присылает клиенту реквизиты. Чек хранится в заказе, пока администратор его не подтвердит
(→ «Оплачен») или не отклонит. «Отправлен в РФ» нельзя поставить без трек-номера.

## Запуск через Docker

```bash
cp .env.example .env     # BOT_TOKEN, BOT_USERNAME, ADMIN_IDS, ADMIN_PASSWORD, SECRET_KEY
docker compose up --build -d
```
Поднимаются PostgreSQL, Redis (состояния бота), миграции, `api` (админка + автокурс)
и `bot` отдельным процессом. Админка открывается на http://localhost:8000.

## Локальная разработка (SQLite)

```bash
make install    # venv + зависимости бэкенда и фронта
make migrate    # создать poizon.db
make api        # API на :8000; с BOT_IN_API=true в .env бот стартует в этом же процессе
make bot        # или бот отдельным процессом
make front      # админка на :5173
make test       # тесты бэкенда
```

## Структура

```
backend/app/
  core/       statuses.py (схема статусов) · pricing.py (формула, Decimal) · service.py (заказы, настройки)
              rates.py (курс юаня с ЦБ)
  bot/        handlers/ (common, calc, order, my_orders, admin) · keyboards · texts · notify · middlewares
  api/        public.py (только вход) · admin.py (админ-API) · auth.py · main.py
  models.py · db.py · config.py
backend/alembic/   миграции
backend/tests/     цена, переходы статусов, API
frontend/src/      pages/ (Login, Orders, Order, Settings) · components/ · api.js · router.js
```

Новая миграция после изменения моделей:
`cd backend && .venv/bin/alembic revision --autogenerate -m "что поменялось"`.
